# rhoSimpleFoam CUDA arm: the fast-path tracker (opened 2026-09-12)

The modules the OF-mirror's CUDA arm gained between 2026-09-08 and 2026-09-12 were ported under the
of-port discipline -- each gated against real OpenFOAM to 1e-11 or better -- and none of them has had a
speed measurement of its own. This table is the list, ranked by what the phase splits in
`../results/rhoSimpleFoam_tutorials_gb10.md` and `../results/rhoSimpleFoam_squareBend_gb10.md` say
each one costs today, with the code it lives in, the gates that must stay green while it is made fast,
the lever the measurements point at, and the number that closes it. The rules are the campaign's
(2026-09-07/08, in the squareBend results file): measure before touching, same stop rule and the same
converged answer after, every arm bit-identical or gated, the gate's bound never loosened.

Reference floor: squareBend at 112k cells, 18.0 ms per iteration in the four phases, 161 ns per cell
(UEqn 3.4, EEqn 2.3, pEqn 8.0, turbulence 4.3; upwind, kEpsilon, GAMG entries substituted by the
device BiCGStab). Every row's "today" is measured against that mesh where it can be.

How to work a row: (1) reproduce today's number with `BRAE_PHASE_TIME=1` on the named case and an nsys
profile with `--cuda-graph-trace=node`; (2) run the row's gates before touching anything, so the bound
they hold is the bound they hold after; (3) build the lever behind a switch that restores today's path
(the campaign's pattern: `BRAE_GS_HOST_SMOOTHER`, `BRAE_READ_SCALAR_SYNC`, `BRAE_U_SOLVER`); (4) measure
the same number again, three runs, and record it in `../results/` with the case, the size and the
switch; (5) flip the default only when the gates hold at their bounds and the number met "done when".
A row whose measurement says it is noise is closed as "measured, noise" with the number, not deleted.
